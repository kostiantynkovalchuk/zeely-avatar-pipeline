# Pipeline Design Decisions

## Evolution of the Approach

### Phase 1: Background Removal + Compositing (BiRefNet)
- Initial approach: remove background → composite on white → IDM-VTON for outfit
- Result: cutout quality, not studio quality. Compared to Zeely's reference outputs (full AI-generated studio portraits), this approach was fundamentally limited
- Decision: pivot to full portrait generation

### Phase 2: PuLID as Primary Generator
- FLUX PuLID generates entire studio portrait from identity reference
- Solved: studio lighting, consistent framing, white background, professional quality
- New problem: identity drift — glasses disappear, hair color changes, body proportions wrong on some users

### Phase 3: Face-Swap for Identity Restoration
- Two-pass approach: PuLID generates body/pose/lighting, face-swap pins real face back
- Solved: glasses preserved, facial features locked to source
- Added user_attributes.json for per-user prompt customization (glasses description, body type, hair color)

### Phase 4: FASHN v1.6 for Text Preservation
- IDM-VTON (UNet-based) warped garment text: GUCCI → GUCCCI, FIRENZE → TRENZE
- Researched alternatives: TED-VITON (academic, not hosted), FASHN v1.6 (pixel-space, hosted on fal.ai)
- FASHN v1.6 preserves text, logos, and patterns by operating in pixel space rather than latent space
- Consolidated entire pipeline onto fal.ai — single API provider

## Why Each Model Was Chosen

### FLUX PuLID (Avatar Generation)
- Preserves facial identity through face embeddings while allowing full body/scene generation
- Generates studio-quality portraits with controlled lighting and pose
- Alternative considered: InstantID (stronger identity lock but less generation freedom)

### fal.ai Face-Swap (Identity Restoration)
- Lightweight, fast (~3s), solves PuLID's identity drift
- Preserves glasses, skin texture, facial hair, moles
- Runs as a refinement pass, not a replacement for PuLID

### FASHN v1.6 (Outfit Transfer)
- Pixel-space model specifically designed for garment detail preservation
- Handles text, logos, patterns, stitching details
- Maskless inference — no manual segmentation required
- Compared to IDM-VTON: better text fidelity, faster inference (11s vs 25s), higher resolution (864×1296 native)

## User Attributes System
- user_attributes.json provides per-user customization without code changes
- Extensible: can add hair_color, skin_tone, accessories, pose_preference
- Glasses detection could be automated with a face analysis model in production

## Known Limitations
- Garment text still has minor spacing artifacts on some outputs (G UCCI vs GUCCI) — fundamental diffusion model limitation
- Face-swap can create visible boundary at the neck on some body types
- Accessories (hats, shoes) are not supported — FASHN handles garments only (tops, bottoms, one-piece). Accessories would require region-specific inpainting (e.g., FLUX Fill for hat on head region)
- PuLID occasionally ignores pose instructions — may require retry
- Body proportions require manual specification in user_attributes.json — could be automated with body estimation models

## Supplementary Experiments
- Hawaiian shirt (Polo Ralph Lauren): 3/4 users produced good results, complex floral pattern preserved well. User 004 had collar bleeding into neck area.
- Cowboy hat: FASHN treated it as a garment and wrapped it around the torso. Confirmed VTON models cannot handle accessories.
- Nike sneakers: avatar is half-body, footwear not visible. Would require full-body pipeline extension.
- Denim jacket (Levi's): button detail poorly preserved, face-swap boundary artifacts on larger body types. Structured garments with small hardware details remain challenging.

## Scalability Considerations
- Current: sequential processing, ~55s per user
- Production: parallel processing with bounded concurrency, job queue (Redis/Celery)
- Cost optimization: FASHN batch API, self-hosted PuLID for high volume
- Quality gate: automated QA → retry with different seed → human review queue for persistent failures

## Infrastructure Decision: Single Provider (fal.ai)
- Started with fal.ai + Replicate (two providers, two API keys, two billing dashboards)
- Replicate had cold-start reliability issues (model stuck in "starting" state)
- Consolidated to fal.ai only — simpler operations, single billing, consistent API patterns
- All three pipeline stages (PuLID, face-swap, FASHN) available on fal.ai
